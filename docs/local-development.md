# Local development and first change

This is the fictional estate's local recipe, added on 2026-10-27. It uses the
committed code and a disposable database. The existing assessment is a dated
snapshot; adding these instructions does not rewrite its result.

## Prerequisites and configuration

- Node 20 (`nvm install` then `nvm use` reads `.nvmrc`) and npm 10. These match
  the major versions in the existing CI path. Install Docker with Compose v2.
- `npm ci` uses `package-lock.json`. Do not replace it with an unlocked install
  to get past a failure.
- `npm run local:env` writes `.env` once with permissions `0600`. It generates
  two random local signing keys and prints no values. An existing file is left
  intact; use a fresh checkout if yours points to a shared environment.
- `docker compose -f compose.local.yml up -d --wait` starts the pinned MongoDB
  image on `127.0.0.1:27027`. Its database files are temporary. Stopping/removing
  it discards local data. It is not a copy of a store or production database.

| Variable | Local source and purpose |
|---|---|
| `DATABASE_URL` | Generated loopback URL for database `copperpot_local` |
| `JWT_ACCESS_TOKEN_SECRET`, `JWT_REFRESH_TOKEN_SECRET` | Separate random local values generated by `local:env` |
| `JWT_ACCESS_TOKEN_EXPIRATION_TIME`, `JWT_REFRESH_TOKEN_EXPIRATION_TIME` | Local token lifetimes `1h` and `7d` |
| `GUEST_EMAIL` | Fictional fallback identity `guest@copperpotbowls.example` |
| `PAYMENTS_PROVIDER` | `stub` for this local rehearsal; no real payment account |
| `GUEST_API_PORT`, `STORE_API_PORT` | Optional shell overrides; defaults 4000 and 4100. The smoke command chooses temporary ports. |

The older `.env.sample` has blank placeholders, including legacy keys. Do not
copy production values into the local path. Signing keys are not returned by the
health routes, written into evidence records, or committed to Git.

## Build and verification

Run from the root in this order:

```sh
npm run build
npm run lint:check
npm run format:check
npm run test:unit -- --runInBand
npm run local:smoke
```

The first four commands are the checks in `.github/workflows/ci.yml`; serial
Jest workers make the local test run predictable on a laptop. `lint:check` and
`format:check` inspect without rewriting files. The shorter `lint` and `format`
commands edit files, so review their diff before committing.

The smoke command needs the built `dist/` tree and the disposable MongoDB.
It starts guest and store applications, verifies their distinct health responses
and HTTP 400 without `x-correlation-id`, and stops both processes, including on
failure. It refuses a different database URL and a non-stub provider. It does
not create an order, charge a payment or test the loyalty ledger.

For an interactive session, run `npm run start:guest` and `npm run start:store`
in separate terminals, then:

```sh
curl --fail -H 'x-correlation-id: local-first-run' http://localhost:4000/api/health
curl --fail -H 'x-correlation-id: local-first-run' http://localhost:4100/store/health
```

Expected JSON identifies `guest-api` or `store-api`, with `status: "ok"`.
These endpoints require the correlation header even though they do not require
a login token. An empty local database is sufficient for these checks.

`npm run test:e2e` is a separate legacy combined-app suite. It is not part of CI
and a passing unit suite does not certify it. Review `test/app.e2e-spec.ts` and
its configuration before treating it as acceptance evidence for either split app.

## First change checklist

1. Pick one CPB documentation or test task with a concrete expected result and
   an owner. Exclude payments and loyalty from a first-change exercise.
2. Start a short branch from current `main`; carry the CPB key in the branch and
   pull request as described in [the workflow](change-workflow.md).
3. Reproduce the current behavior. For a documentation correction, follow the
   affected command from a fresh checkout. For a test change, show that the test
   fails for the defect before changing the implementation.
4. Make the smallest change, run the affected check, then run all five commands
   above. Review `git diff --check` and `git status --short`; `.env`, dependencies
   and `dist/` must not be staged.
5. Open the PR with the ticket, exact commands/results, remaining limits and QA
   handoff. A reviewer and the release owner take the next steps. Local success
   alone does not complete review, release or deployment.

## Troubleshooting and cleanup

| Symptom | Check |
|---|---|
| A required configuration variable is missing | Run `local:env` in a fresh checkout; do not fill blanks with shared secrets. |
| MongoDB connection refused or smoke times out | `docker compose -f compose.local.yml ps`; then check that port 27027 is free and Docker is running. |
| Health responds 400 | Supply `x-correlation-id`; the missing-header check deliberately expects 400. |
| Port 4000 is already in use | Stop your own combined/guest process or choose `GUEST_API_PORT`; the smoke command uses temporary ports. |
| Native dependency installation fails | Confirm Node 20/npm 10, then retry `npm ci`; retain the failing install log for diagnosis. |
| A command rewrites files | Prefer `lint:check` and `format:check`; inspect edits before including them. |

Stop interactive servers with Ctrl-C and run
`docker compose -f compose.local.yml down --volumes`. This affects this Compose
project only. Keep or remove the ignored `.env` according to whether you will
reuse the checkout; never include its contents in a ticket or log.
